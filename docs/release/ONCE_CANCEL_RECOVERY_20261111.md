# ONCE 上传取消回执与旧状态读取验收（2026-11-11）

## 版本与范围

以 Draft PR #41 的 `f4398e856f4573efcdecbb628b7dbe3594a2db4c` 为固定基线；此前验收只覆盖取消返回 200 和旧 `RECEIVING` 响应晚于 `FAILED`，不能代替本次场景。本轮未发现需要修改的产品代码。结果 JSON 的 `head` 为运行时基线；生产源码、测试脚本和已测构建产物的 SHA-256 分别记录在结果中，后续提交须按指纹核对，不能把旧 CI 算作新提交通过。

使用登记的临时 PostgreSQL、Nest、Chromium、本地媒体存储、本地验证码网关和合成账号/图片；没有真实 COS、认证或通知。丢响应测试先让真实取消 POST 返回 200，在数据库确认事务、回执和审计后才向浏览器丢弃响应。旧读测试先由测试进程持有本地部分 PUT 并确认服务端 `RECEIVING`，再让浏览器读取真实草稿响应；未通过 SQL 修改业务状态。截图为 390×844 合成视口。

## 实际结果：6/6 PASS

- **同页取消响应丢失。** 服务端已提交 `CANCELLED`，上传版本恰好加一，有一条指向原上传的取消回执和一条取消审计；页面保持“结果需要核对”，取消与选择新文件均禁用。实际重复点击禁用按钮不产生第二次取消请求。核对时原 POST 使用相同幂等键和请求体，服务端 HTTP 200 且 `replayed:true`；等待中再次点击被禁用，上传数、额度、素材、回执、审计和版本均不变。
- **刷新后核对。** 同一标签刷新后保留待核对状态；点击核对只执行一次原回执 GET（HTTP 200，目标与上传版本匹配），不再次 POST 取消，之后显示已取消。两条未物理清理的合成记录仍占 6466 字节。
- **旧状态晚到。** 当前页面已实际显示 `CANCELLED`，且取消操作及后续较新草稿读取结束后，才交付此前真实取得的 `RECEIVING` 草稿响应。浏览器实际消费的上传状态/版本顺序为 `CANCELLED/3 → CANCELLED/3 → RECEIVING/2`；MutationObserver 在交付后及 350 毫秒观察窗口内未见终态倒退为处理中或等待传输，未出现旧状态错误提示。取消记录、唯一回执、审计、素材数、额度和版本保持不变；随后刷新仍显示已取消。
- **没有回执的负控。** 测试让另一次取消请求在到达服务端前中断；刷新后两次实际读取原回执均为 404，页面仍提示保留核对标记并禁用新上传，没有重新 POST、取消回执或取消审计，原上传仍为 `OPEN` 并继续占额。此行为没有证明用户可自行解除待核对；如持续无回执，需人工协助或另定受控恢复方案，不以 404 推断迟到请求不可能提交。

本次额度根据未清理上传的 `expectedBytes` 检查；三条取消记录及一条未完成记录最终分别合计 9699 和 12932 字节。没有因逻辑取消宣称物理删除。回执核对使用有效同意下的同一合成账号；未因此推断撤权或过期后的回执仍可读取。检查的是数据库命令回执与取消审计，不等于已检查全部安全意图日志。不同客户端使用最新版本和新幂等键发起的独立创建不在本次全局去重声明内。
