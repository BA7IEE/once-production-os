## P01：专业替换与目录恢复

F01 已先复现：当 replace 包含摄影与导演的两条同名字段，而新答案仅包含摄影字段时，原实现返回 200。失败用例保留在 `artifacts/once-upgrade/p01/core-before.tap`。修复后使用每个旧事实自己的 `roleCode + fieldCode` 对应新答案，并拒绝重复替换 ID；所有检查先于事实退役和本人可见项修改。

覆盖整批少一个答案、跨职业同名字段、重复 ID、明确 `NOT_PROVIDED`、来源停用。拒绝后比较原事实、本人可见项及人物版本；成功后核对旧事实保留为 RETIRED、新事实与本人视图同步。真实 PostgreSQL 另覆盖数据库约束下的整组原子性。

F02 已先复现：专业已应用条件及未应用编辑不进入原目录历史。现在一起保存于版本 2 的既有 history state，继续绑定成员与会话范围。仅保存有界字段编码、选项、状态、数值/日期/布尔比较和候选 ID；拒绝未知字段及正文数据。未应用的能力空选择保留为编辑草稿。返回、前进后退和刷新均从这个状态恢复，然后重新请求当前可见结果；旧版本、退出、失效与新会话恢复为空状态。

## P03：扩展事实合并与 v16 业务迁移

含扩展事实的合并现在进行完整扫描，枚举双方的字段当前值、目录版本和来源。同一人物字段冲突须逐项明确选择；不同职业的同名字段不相互覆盖。保留根事实、记录组及每个分项和选项 UUID、ACTIVE/RETIRED 历史与原来源；移动文字按主人物绑定重新加密。原专业主档保留在现有合并历史中，已有维护授权和用途许可撤销，不扩大到主人物。旧 ID 与合并决定仍不可变。

精确作品署名在本包受支持的扩展资料合并路径中逐项确认，保留精确职业与原署名来源；同一事务移动职业、署名和候选引用。仍不支持重叠同职业扩展资料的自动换绑、冲突精确署名和受限/版本已变化的来源。相关组合明确阻断并保留两份档案，不能靠填写迁移确认绕过。

第 80 次迁移在原事实不可变校验上增加受约束的身份移动：数据库要求同事务存在真实的追加合并决定、旧 ID 映射，且决定逐项列出所移事实。普通数值改写、伪造 merge ID 或没有对应映射的移动仍失败；未关闭原约束。增加原环境确认归属元数据，引用原工作区、来源、员工或本人及确认时间，不冒充目标账号。

内部导出单独选择并批准 `person.td2.supplierFields`，人才与全部实际来源均需许可，随同专业主档和精确职业迁移；合并过的资料还需批准合并历史。容器继续采用专业导出契约，人才 bundle 明确升级为 v16，内含版本化 `once-supplier-transfer-v1`、字段目录定义/摘要、全部事实与选项、成组记录和历史。旧 v14/v15 文件继续按原范围接收，不接受夹带 supplier 块；旧导出请求遇到扩展资料继续拒绝，不能漏掉事实后生成文件。补齐资格名称的既有可选迁移字段。

重建先检查目录版本/编码、类型、归属、选项含义、记录组、精确职业、原来源版本及合并历史；冲突或原密钥错误时没有写入。使用现有私有密钥文件流程，在目标工作区和密钥下重新加密文字。目标不导入活动维护授权或原用途许可。真实 PostgreSQL 使用两个本轮隔离数据库，执行实际 CLI 预检与应用；父容器退出后两个库一起销毁。
