# M1｜私有静态图片开发切片

输入基线：`683b9a18d5fbd1e9b465bb3ef5b46737978ab8ab`（H1 / PR #3）。
分支：`feat/private-media`。与当前阶段里程碑 **M1** 不同，本文的 M1 是媒体的第一个增量代号，不表示整个里程碑已经完成。

## 1. 用户可完成的操作

人才详情的“关联私有图片”选择单张文件，或“私有图片”页选择可读来源后上传。客户端计算摘要；服务端建立有额度的上传记录；流式接收私有文件；用户提交检查，Worker 新位置封存、复核摘要、独立解码并重新编码预览；最后同一个数据库事务产生资产与 READY 状态、审计。

JPEG / PNG / WebP，单文件 30,000,000 字节，静态单帧，最多 60MP。预览为最长边不超过 1600 的 JPEG；不使用原件作为浏览器预览，不保留 EXIF/XMP/ICC。这不是人脸匿名化，不删除图片画面本身的文字/人物。方向应用后预览尺寸可能与原始存储尺寸对调。

PDF / MP4、原件下载、批量拖拽、多文件断点续传、COS、AI、作品绑定和删除整个媒体库，**本批尚未实现**；不是从一期永久取消。当前媒体可选择关联一个人才，来源必须是该人才主来源；独立来源图片也可入库。作品模块未来消费稳定 Asset ID，不把对象路径当业务标识。

## 2. 授权：不改变 H1 交接的含义

ADMIN/EDITOR 有 assets.read/upload；REVIEWER/VIEWER 有 assets.read。所有入口仍需有效内部身份，资料范围和来源有效用途。ADMIN 无全局范围旁路。

只采用**原生范围**；H1 基本档案交接不会获得图片元数据、上传、原件或预览权。关联人才时同时检查人才原生范围与来源。资产保存创建时 scope，上级范围变化后取交集，不因旧图片扩大可见性。

来源暂停/到期，下一次列表、详情和预览读取立即按当前规则拒绝；显式重新核准来源后按新的合法当前范围判断。隔离 Asset 则不可预览，本批没有解除隔离入口。不能收回之前已经显示/截图的内容。

“我的上传”只给上传人最小状态、文件名、错误码，以便在来源失效后取消/核对；这不是文件访问权。传输/解码时固定成员版本、会话保护版本、来源版本/保护版本、范围版本及期限；变化后不能发布 READY。

## 3. 上传、后台任务和文件一致性

状态：OPEN → RECEIVING → UPLOADED → QUEUED → PROCESSING → READY；FAILED / CANCELLED 终止。

- 建立、续期、完成、取消、隔离都是正式幂等命令；记录、最小审计、回执同事务。
- `complete` 返回 202，表示排队，不表示检查成功；前端继续读上传状态。
- 二进制接收不是可盲重放的 JSON 命令。OPEN 只能领取一次；响应丢失先 GET 核对。不会覆盖已收到的 staging。失败/中断后新建上传，而不是续写旧路径。
- 完成响应未知时前端保留**原键和原 expectedRevision**，即使轮询获得新版本，也先原样核对旧完成命令。
- 文件接收在数据库事务之外；长度、摘要、当前资格在接收结束重新确认。暂存写为排他创建，fsync 后才能标记 UPLOADED。
- 每个处理 leaseToken 使用全新 work 目录，绝不原地覆盖 final。先拷贝并验证 final，再解码 final。失去租约的旧 Worker 不能写业务 READY，也不能覆盖新 Worker 的预览。
- 最长 3 次租约领取，30 秒租约，10 秒心跳，1 小时处理截止（不晚于来源截止）。暂时宕机可重新领取；明确文件错误不盲目重试。
- 新 Asset ID 等于 uploadId，数据库保证同一上传只有一个资产。原始两层模型身份独立于文件名；objectToken/路径/摘要不进入普通响应。
- 失败/取消后 24 小时才清理登记的目录；先原子移到私有 trash 再清除，终态不重新开放，因此迟到写入不能通过递归 mkdir 恢复旧路径。READY/QUARANTINED 不在本批自动删除范围。
- 清理前复查维护模式、恢复版本和对象状态；恢复操作必须停止原 API/Worker，不能一边运行旧 Worker 一边覆盖磁盘/数据库。

默认每人 3 个、每空间 20 个活动上传，活动声明 1GB，未清除声明存量 2GB；每人每小时 100 次建立，历史记录最多 50,000。额度是**保守应用准入，不是精确物理磁盘封顶**：staging、最多三份尝试、预览和文件系统额外空间需独立磁盘/卷配额与告警。正式部署不应只依赖这些计数。过期但未处理记录仍占额度，清理成功才减少存量。

列表复用既有事务内批量原生可见性索引，不逐图片重复访问权限表；仍有应用层筛选/分页及全局事务锁，尚未达到负载目标验收，不擅自删锁。

## 4. HTTP 和存储

新增 11 条接口（总请求契约 57 条）：POST/GET uploads、GET upload、PUT upload/content、POST renew/complete/cancel、GET assets/asset/asset-preview、POST quarantine。

PUT content 只接受 `application/octet-stream`、明确 Content-Length、无压缩、无查询参数、同 Origin + CSRF + 内部会话。有界流最多 30MB，60 秒接收截止。不接收任意 URL，不提供 fetch-url/远程抓取入口。

预览是同源**鉴权字节流**：取权限 → 读/验证最大 5MB 的 JPEG → 重新检查会话/范围/来源/资产版本 → 返回。禁缓存、nosniff、CORP same-origin；不返回对象签名或公开地址，不把整个媒体目录挂到 express.static。

LocalMediaProvider 使用绝对独立目录、登记标记、0700 目录、0600 暂存、0400 封存；拒绝已有非空且未登记目录，不接管既有文件。路径只来自 UUID；符号链接根拒绝；文件排他创建并 O_NOFOLLOW。此实现假设 OS 用户和私有根可信，不是跨宿主恶意管理员的隔离方案。

`MEDIA_PROVIDER=local` **仅允许 APP_ENV=local/test**，`MEDIA_ROOT` 必须绝对路径；默认 disabled。staging/production 不可通过仅设置 local 来启用，正式 COS/容器卷和安全边界待独立验证。禁用时不启用假存储或内存回退。

## 5. 图片解析及依赖

sharp **0.35.4** 与 pnpm-lock 由隔离 Linux Runner 真实解析，随后冻结安装。该次生产依赖审计为 0 个已知漏洞，不等于没有未知漏洞。

先检测真实文件头，只允许 JPEG/PNG/WebP；sharp 再按相同格式、严格解码、60MP、单帧验证。子进程最多 60 秒，V8 堆限制 128MB；Linux 对含原生分配的 RSS 每 100ms 监视，超过 256MiB 杀进程。环境仅保留 PATH/LANG/VIPS_CONCURRENCY，没有数据库 URL、应用密钥或 NODE_OPTIONS；标准错误不收录恶意文件原文。

**子进程、内存监视不等于完整 OS 沙箱或无网络保障。**存在采样间隔、原生解码器及同 UID 风险。正式处理不可信真实素材前仍需无网络、受限 UID/挂载、cgroup/seccomp 等部署验证；因此本批不开放 production/staging。不要称为已完成病毒扫描或安全认证。

sharp 原始文档：
- https://sharp.pixelplumbing.com/api-constructor/ （格式、failOn、limitInputPixels、多页限制）
- https://sharp.pixelplumbing.com/api-output/ （默认移除元数据）
