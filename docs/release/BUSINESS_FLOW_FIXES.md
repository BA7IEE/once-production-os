## 业务闭环及实际改动

| 原断点 | 本轮处理 | 仍需人工判断的边界 |
| --- | --- | --- |
| 默认编辑员快速建档后，私有临时来源无法送交外部范围的核验人 | 新增“核验与共享”：维护人发起 → 核验人接受 → 核验依据 → 指定管理员确认范围 → 团队读取 | 核验来源不等于确认所有字段；共享来源关联其他人才或独立业务记录时，拒绝单人流程扩大范围 |
| 导入显示成功，新人才目录却筛不到职业和城市 | 新页面提交 `once-talent-import-v2`；人才、职业、常驻地和逐行检查点同事务写入；普通联系人保持普通联系人 | 同名不合并；普通联系人导入暂仅接受姓名，不把职业和城市悄悄丢掉 |
| 旧导入只有旧字段 | 导入任务增加“核对专业档案补齐”，保留原 Person ID、来源、检查点；独立命令显式确认 | 不覆盖已有专业档案，不绕过隐藏候选清单，不把旧身高自动当作已核验量尺 |
| 本人端任何 422 都把表单锁死 | 明确拒绝允许修改；未知结果保留原键、正文和原账号；成功后刷新失败只重读 | 刷新页面后仅保留最小核对标记；找不到回执仍是未知，不能据此再发一次 |
| 主详情同时修改不同来源的字段时整笔失败 | 人口学信息、模特分类、常驻地、量尺分别携带各自来源版本；修改已有记录同时绑定记录 ID 和版本 | 任一项目过时或无权使用时整体回滚；不同来源的提议继续逐项采纳，不混入普通保存 |
| AI 任务需要原文，页面却没有原文入口 | 来源页新增文字来源；符合资格时在详情编辑原文，沿用受限权限和历史记录 | 此改动不批准 AI 外发，不绕过任务授权、预算和人工采纳；本人同意来源不能追加内部材料 |

## 核验授权与状态

业务状态为 `PENDING → ACCEPTED → REVIEWED → PUBLISHED`；未结束任务可以由发起人撤销、核验人或指定发布人退回。资料版本、保护代次、成员版本、当前权限、原范围或目标范围变化、恢复代次变化、删除阻断及任务到期都会让未结束任务失效。

| 参与者 | 接受之前 | 接受之后 | 核验之后 |
| --- | --- | --- | --- |
| 人才和来源的共同维护人 | 只能为自己原本可维护的单人资料发起，明确选择核验人、发布人、目标范围和最长七天期限 | 可撤销；不能借任务向别人转授权 | 等待管理员确认范围 |
| 指定核验人 | 只读最小任务信息并决定是否接受 | 只在本任务读取当前指定人物姓名及当前来源材料；原文另外要求 `sensitive.read` | 核验材料授权关闭；普通来源、联系方式、附件和历史接口始终按原有权限处理 |
| 指定发布人 | 必须当前有 `members.manage` 且能够访问目标范围 | 不获得核验原文读取权 | 查看本次人物、核验依据和目标范围，再明确确认共享 |
| 其他成员，包括范围外管理员 | 不获得任务、人物或来源的额外读取权 | 同左 | 只有确实属于最终范围且具有相应字段权限时，才能通过正式接口读取 |

仅 `source-review.ts` 使用这个有限授权。原始 `source.get`、历史、联系方式、媒体及普通 handoff 不消费该授权。业务状态、来源历史、审计和命令回执处于同一事务。任务不复制原文；结束后参与者只能读取最小任务状态。回执重放仍在 `replay-policy` 鉴权，不在 Commands 塞入领域统计或原文。

过期草稿允许共同维护人从核验页重新发起任务；候选列表不回显过期人物原文。接受新任务不会延长来源期限，核验人必须独立填写新的真实依据和期限。暂停、擦除、删除阻断及受本人同意约束的来源不通过这条流程扩权。

## 新旧导入和历史补齐

`ImportBatch.formatVersion` 默认 `1`，旧 API 不传版本仍创建旧批次。新版页面显式传版本 `2`，任务类型为 `IMPORT_TALENTS_V2`。新 Worker 同时识别两种协议，批次与任务版本不匹配即终止，不重新解释已提交的行集合。

旧批次原样处理完毕后，另行预览补齐。预览不再依赖最初的 24 小时预览期限，但仍要求发起者本人、当前来源、人物和各相关来源范围有效。每次最多 20 行，逐行绑定人物及来源版本：

- `READY`：尚无专业档案，旧职业、城市、语言、能力字典有效，相关候选关系有权处理。
- `COMPLETE`：已有专业档案，旧导入对应的专业字段已经存在。
- `REVIEW_REQUIRED`：已有不完整或更改后的专业资料、字典失效等情况，不能自动覆盖或恢复旧值。
- `BLOCKED`：当前无权处理或资料状态不允许。只返回行号和原因代码，不泄露隐藏记录的姓名或关联内容。

新迁移增加 V2 检查点约束：即使旧 Worker 错误领取新版任务，也不能只创建旧字段后就把人才行标记为 `IMPORTED`。此约束的 SQL 已加入真实 PG 用例，当前尚未实跑，不能视为数据库验收通过。

## 本人端未知结果恢复

原请求正文只在当前页面内存中保留。浏览器仅保存账号 UUID、请求 UUID 和是否需要定位新草稿的布尔标记；不保存姓名、原文、cookie、凭证、完整正文或回执内容。

页面刷新后通过 `GET /portal/commands/{id}` 只读核对。服务端重新认证当前人才账号，并按原回执对应领域检查当前资格；其他账号不能读取。收到有效回执后读取当前资料，定位已创建的服务器草稿，再移除标记。网络异常、回执格式异常或未知之后收到拒绝，都不能擅自换新请求键。

## 迁移、上线顺序与回退

新增迁移 `202610030001_business_flow`，累计 75 次。1–74 不改写，旧批次默认版本不重算。该迁移**尚未应用到真实数据库**。

上线前必须先停旧 Worker，核对 RUNNING 任务的租约和检查点，完成备份及隔离升级验证。然后追加迁移、生成 Prisma Client，部署同版本 API 和 Worker，确认版本协议后才开放新版页面。旧任务继续旧语义，历史补齐另行确认。

禁止新旧 Worker 混跑。需要回退时先停新写入和 Worker，保留所有新表及数据；不能删除迁移、回退 schema 或启动不理解 V2 的 Worker 来“恢复”。先检查 V2 批次、未知回执和未结束核验任务，再选择禁用新入口或向前修复。

3. 执行完整 `pnpm typecheck`、受保护的 `pnpm build`，再做真实浏览器验收。
4. 浏览器至少走默认 EDITOR 私有建档→核验人接受→管理员共享→团队检索；新导入职业/城市及普通联系人筛选；旧导入补齐；跨来源保存；来源原文录入→AI 输入选择；本人端空提交 422、写后断网、刷新断网和账号切换。保留失败证据，不能用 API 或组件通过替代。
