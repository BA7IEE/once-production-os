# SL1｜内部候选清单开发与验收说明

日期：2026-09-24。输入基线：WP1 `c349af4f3cb8515c619f50836d79bac828aad34b`。开发分支：`feat/internal-shortlists`。

本批落实 FR-15 的内部候选主链路，并补充 FR-12/14/28 的权限、失效和幂等约束。没有客户分享、匿名链接、档期、报价、合同或官网发布。

## 1. 本批范围

- 每个候选清单必须绑定一个当前可见项目，清单访问跟随项目当前来源和范围；不会另造一套公开权限。
- 清单可保存标题、需求说明、状态、人才候选和参考作品。
- 人才候选支持排序、分组、协作备注，以及 `候选 / 优先 / 已联系 / 暂不合适` 四个内部状态。任何状态都不表示档期确认、预订或项目实际参与。
- 参考作品独立排序和备注。加入清单不改变 Work 制作归属，也不生成项目作品关系。
- 加入时保存人物/作品及来源版本。读取时提示底层资料是否已变化；始终展示当前允许的资料，而不是冻结旧快照。
- 当前依赖失效时只保留清单本地关系占位及位置；不返回隐藏人物/作品身份、分组、状态或备注。维护者仍可移除本地关系。

## 2. 数据模型

新增三张表：`shortlists`、`shortlistPeople`、`shortlistWorks`。追加迁移 `202609240002_internal_shortlists`，原五条迁移不改写。

Shortlist 以 Project 为权限根；候选关系只引用 Person/Work，不授予其访问权。所有子关系写入使用 Shortlist 父 revision CAS，排序要求提交完整排列。位置唯一约束使用延迟检查，允许同事务交换顺序。

## 3. 接口

新增 11 条内部接口：清单列表/创建/详情/更新；候选人才新增/更新/移除/排序；参考作品新增/移除/排序。写接口均走既有 Commands、幂等回执、事务审计和重放授权。

## 4. UI

管理端新增“内部候选”一级入口：按项目建清单、加人、排序、分组、记录内部状态和备注、添加参考作品、显示“加入后资料有更新”。没有分享、客户确认、报价、档期或预订按钮。

隔离编辑副本已实际执行新增 8 项 MemoryStore 核心测试通过；并分段回归 WP1/R1/Talent 测试通过。统一完整测试、Prisma validate/generate、真实 PostgreSQL、React/Vite 构建与 Chromium 验收以该 PR 最终提交对应 CI 为准；本文件创建时不预写通过。

## 6. Review 边界

- 清单本身不能作为人物/作品访问授权来源。
- H1 基本档案交接不会因此获得候选、作品或项目额外权限。
- `CONTACTED` 只记录内部沟通进度，禁止被解释为有档期或已预订。
- 候选清单不会写 `projectParticipants`，不会增加实际项目数。
- Project 来源暂停或范围失效后，整张清单不可读取；单个人才/作品失效只脱敏对应条目。
- 审计列表对 shortlist 使用同一项目权限根过滤，ADMIN 不绕过范围。
