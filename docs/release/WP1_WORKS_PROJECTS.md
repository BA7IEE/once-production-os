## 1. 已实现的操作

作品库：建立草稿 → 选择已上传且可读的 READY 图片 → 调整顺序和封面 → 添加人员及贡献角色 → 标记使用中、归档或恢复草稿。可以先无图片建草稿；使用中至少有一张有效图片及本作品的封面条目。移除最后一张图片会回到草稿。

项目库：不依赖 CRM/报价/合同即可建立项目；记录标题、需求、地点、日期说明和内部复盘；人员按“提名／确认／实际参与”分别记录；作品按“参考／交付”分别关联。实际参与必须填写发生的工作或依据。完成项目不自动建立账款、锁档、合同或人才核验。

人才详情：展示当前可见的署名作品、项目参与记录及去重后的实际参与项目数。一个人同时摄影和剪辑只计一个项目；提名、确认、上传素材或添加作品署名均不产生“实际参与”业绩。

作品来源明确标记 UNKNOWN、EXTERNAL、ONCE。ONCE 标记必须有人工填写的制作依据，但该字段不是认证。外部作品被项目用作参考或外部交付时，仍保持 EXTERNAL；不会因关联而改写原作品归属或生成制作团队。

## 2. 数据与归属

追加六张表：`works`、`workAssets`、`workCredits`、`projects`、`projectParticipants`、`projectWorks`。

Work/Project 根各自有来源、维护人、访问范围、版本和状态。新根继承当前来源范围，维护人固定为创建成员。本批不开放修改根的来源、范围或维护人，未来受控转移须独立实现，不能通过任意 PATCH 参数绕过。

WorkAsset 是有顺序的关系，不是文件本身。封面引用 **WorkAsset.id**，通过 `(workspaceId, workId, entryId)` 组合外键保证属于同一个 Work。条目位置唯一约束和封面外键在提交时检查，支持同事务互换位置及移除封面。`Prisma` 不表达约束延迟属性，SQL 迁移是该属性的依据；禁止用 `db push` 覆盖。

WorkCredit 和 ProjectParticipant 都引用现有人才及贡献角色。一人可有不同角色，同一父对象下同人同角色不可重复。贡献角色不要求等于人才档案的现有职业：历史拍摄中的贡献是另一项事实。新关系只能选择启用角色；停用字典不删除历史记录，已有参与状态仍可据实更正。

限制：每作品30张图片/50条署名，每项目50条参与/30个作品关联。这是本切片的录入边界，不是全库性能指标。根的列表暂使用当前 Store 的应用层授权过滤和分页；没有移除全局事务锁，不声称通过负载指标。

## 3. 权限与实时失效

读根需要 `records.read`、根范围及当前来源有效；写根/关系还需 `records.write`。ADMIN 不绕过资源范围。来源到期、停用或范围收窄按当前事务即时判断，不等待定时任务。

被引用图片还要检查 `assets.read`、图片状态、图片/来源/关联人才的原生范围。人员署名和项目参与使用原生 `personFor`，**不使用 H1 限时基本档案交接资格**。项目作品检查目标 Work 当前资格。关联不会扩权。

根可读但子依赖不可读时，返回有限占位：只保留本根下的关系编号（图片还包括位置与是否封面），不返回隐藏对象 ID、文件名、人员名、角色、关系说明或笔记。此处“不可用条目存在”是根范围内允许的信息。维护人仍可移除本根内的占位关系；不会删除被引用的文件、人才、作品。

反向作品/项目经历只计当前可见的父对象。审计列表也用同样的根鉴权，不允许通过日志枚举私有作品。普通审计只记字段名，不记录完整说明和关系请求正文。

已显示或截图的内容不能远程收回；这里保证的是当前 API 新读取不继续返回已失效依赖。客户分享、网站发布都没有实现。

## 4. 命令和前端一致性

所有写动作使用既有 Commands：当前账号及动作权限 → 同 actor/op/key 回执检查 → 新命令的父版本 CAS → 写根/关系/审计/回执，全部同事务。

回执始终是根 ID、版本及操作结果，不包含人才联系方式或素材身份。原样重放不重新执行 CAS，也不重新插入关系；但先检查当前根和来源资格。关系删除后的旧成功回执不复活关系。

排序提交完整条目排列与封面条目，拒绝遗漏、重复、跨作品、陈旧版本。所有关系修改增加父版本，以防两个编辑者各自覆盖同一个集合。引用更新不暗改被引用对象。

新表单在写入结果未知时保存原操作、参数及请求体，锁定表单，提供“核对上次提交”。不会生成另一份不同内容的命令。分页与核对按钮均为 `type=button`，避免嵌入表单时意外提交。接口失败保留录入内容。

## 8. Review 已处理

- 私有素材不得因加入工作空间可见作品而被额外返回；子依赖实时逐项鉴权，存储错误不伪装成无权限占位。
- 封面不能只检查 asset.workspaceId，必须有同作品组合 FK；排序用父 CAS 和延迟唯一约束。
- 删除关系仅删本根条目，错误父 ID 拒绝，引用实体不随之删除。
- 对外部作品的 DELIVERABLE 不自动改成 ONCE；署名不等于实际参与；同人不同角色按项目去重。
- 只读角色、H1 接收人、失效来源都不能借关系扩大访问。
- 前端不使用首次更新留下的 DOM/旧数据库状态证明第二次重放成功，等待真实第二次响应和 `replayed=true`。

首轮新增核心测试发现两处测试构造问题：审计查询使用了不存在的旧猜测路径、测试补丁中用了未定义的 scopeId 被 JSON 省略。已改为实际 `/audit-events` 路径和有效伪造 UUID，断言不放宽，随后30项全部通过。
