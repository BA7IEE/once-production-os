# 已删来源保留资料的导出与重建

来源已经完成删除，但专业资料因独立字段依据保留时，所选资料可进入 v12 迁移格式。导出仍要求人物字段许可、字段证据许可，以及每份当前依据来源对相应专业字段的许可。已删来源不会出现在可批准来源列表，也不作为当前来源导出；它只保留 id、revision、protectionEpoch、ERASED 四个字段，用于保存原始事实归属。

每个保留字段必须附带另一份当前有效、版本匹配、值一致的登记证据，包括空值和有效期边界。原核验归属原样保留；本来没有核验归属的证据仍为空，不伪造目标管理员核验。缺证据、摘要不符、来源版本或有效期不符，以及现行来源与已删来源编号碰撞均拒绝重建。已删来源头不能被用作人物身份、机构、原件或现行证据的来源。

重建使用原 UUID 插入最小 ERASED 来源头，去掉提供方、原文、核验者及核验时间，并设置已经过去的时间范围。正常来源入口即使没有旧环境删除申请，也拒绝重新核验、暂停和使用该来源。资料仍通过独立字段依据可读，再次导出继续保留原字段和核验归属。恢复的是业务关系，不是已销毁的来源内容。

整批重建与审计同事务。真实 PostgreSQL + CLI 已验证预览、执行、审计失败回滚、再次迁移及已删来源禁止重新启用。原 v1～v11 格式不增加字段、不改变摘要；v12 使用完整明确白名单。本批没有新迁移。
