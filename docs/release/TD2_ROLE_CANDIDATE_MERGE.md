# 人才 2.0 按职业保留候选的合并｜2026-09-27

接续 PR #26 Draft `1cd4e2205a416dab7761b5cd9bc26d0a75ce0532`；基线 Actions `36310992401` 五条通过。本轮继续开发，不合并、不部署。

## 问题和行为

候选新增接口已经按“人物、作品、职业记录ID”区分候选；人物合并仍只按“人物、作品”寻找冲突，专业扫描也将同清单/同作品的不同职业记录统一阻断。结果是两份人物档案分别有模特或翻译候选时，无法保留独立的职业上下文。

合并现在按同一作品和同一职业记录ID识别真正的候选碰撞。不同职业记录分别保留原候选ID、职业ID/记录版本、备注、选图关联和迁移复核记录，只把重复人物关联移到主身份，不把另一候选删除，也不把同职业代码的不同资料记录强行合成一个。职业事实冲突仍须显式决定哪份生效；停用职业的候选继续存储，按原规则显示不可用，不自动换绑到另一职业。

专业候选迁移加入逐项确认清单；漏确认返回 `TD2_MERGE_DECISIONS_INCOMPLETE`。页面用“职业候选（保留职业、备注和选图）”标识。其他作品署名、项目参与和普通旧候选的原冲突规则保留。

清单范围、关联作品/素材及素材读取权限在当前事务检查；不可读依赖隐藏专业明细并阻断。清单、候选、选图关系和素材状态进入预览摘要；旧预览不能在这些依赖改变后执行。候选数量计入既有500条专业图上限。迁移、职业冲突决定、别名、回执、审计继续同事务，审计失败后原请求键可重试。

## 保留的阻断

两份职业不明候选确实落在同一候选位置，且有关联迁移复核记录时，继续返回 `TD2_MERGE_SHORTLIST_CONFLICT`，不能为了合并删除复核证据。无职业上下文的历史候选清理/整合仍需要专用流程。已合并专业历史的删除策略也仍未完成。

本轮没有新增迁移，不把应用层候选查重说成数据库唯一索引；现有外键和位置唯一约束继续执行。
