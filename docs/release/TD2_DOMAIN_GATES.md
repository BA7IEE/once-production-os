## 带旧数据的升级

`tests/postgres/talent-baseline-upgrade.test.ts` 要求显式授权的新空库 `once_test_td2_upgrade_*`。先复制 TD2 之前的冻结迁移到临时目录并部署，写入仅供测试的旧版合成数据，再在同一个数据库部署当前全部迁移。没有 `db push`、清库或替换旧迁移。

- 升级前每张已填充业务表逐行保存所有旧字段；升级后逐字段比对，包括 Person/Work/Project/Asset UUID、原文字段、时间、版本和候选备注。
- 对照 `_prisma_migrations` checksum 和仓库全部迁移摘要，证明部署使用冻结原件。
- 检查职业、GENERAL 能力、等级为空的语言、BASE 地点正确回填且保留原来源。
- 原身高不生成量尺或 CastingProfile；两个身高进入待确认队列。
- 单职业候选自动绑定对应职业；多职业候选保留原候选 UUID，进入人工复核。
- 以正式登录和查询接口对照初始回填状态下职业/语言/常驻地的旧、新查询结果。
- 未确认身高和未知语言等级不能被组合筛选误计入。

本批该独立升级用例 1/1 DB_TESTED，扩充旧原件元数据后再次通过；实际媒体文件及物理恢复由领域/恢复套件验证，未把元数据回填当作文件恢复。完整 PostgreSQL 验证链 DB_TESTED（原合同 67/67、领域 17/17、旧基线升级以及所有既有重建/恢复套件）。类型检查、请求契约 167 路由、静态检查 11/11 PASS。所有成功与失败的合成库保留供核查；只删除本测试创建的临时文件目录。
