# 人物身份的独立依据保留

日期：2026-09-28。延续 PR #26，基于 `735652fa0153b931ebd519aaa7cb6e8b8fd12db7`；该 head 的 Actions36351620769 五条验收均通过。本批新提交的云端结果须另行核对。

## 实现

- 来源删除中的人物身份可独立选择保留，不再把 Person.sourceId 改为另一个来源。此列仍承载最初来源编号；删除后的原来源只剩最小 ERASED 头。
- 姓名、别名、简介必须有现成、当前、同值的独立字段依据；空别名和空简介也须核验。仍存的旧职业、城市、语言、技能、身高值同样逐项检查，不能借身份保留绕过专业迁移。
- 旧持久化人物来源重绑计划明确阻断，不能绕过新规则执行原先的来源改写。
- 专业事实与身份分别决定；删除身份后不能保留其专业事实或作为经纪人的关系。保留身份时，其他人的代表关系可以在完整现成依据支持下保留。
- 独立来源的联系方式、媒体、作品/项目关系、内部候选及候选图片可分别确认保留。原件、作品、项目或候选本身另有删除决定时，不能只凭人物保留决定绕过删除。联系人密文不解密、不进入审计。
- 删除来源的证据和建议清理；其他独立核验的来源、摘要和原审核归属不改写。没有专业档案的普通联系人不会被自动转成人才。
- 冻结图覆盖身份、跨来源专业资料、联系方式/上传、候选和关联范围。整组业务修改与审计同事务；执行及最终完成重新检查资格、范围、依据有效期和被冻结的来源版本。
- 原来源已删除的人物按当前字段依据读取，普通列表与 SQL 候选检索也遵守同一限制。依据暂停或失效立即失去对应可见性。旧身份编辑接口明确要求使用独立来源字段建议，避免写出没有依据的新身份值。
- 保留依据读取仅在存在 ERASED 来源时增加批量证据查询；既有 100×100 导入读取预算未放宽。
