# 内部中英文文本：人工维护、依赖、删除和恢复

基线 `779d11c41cb91849858dde6605cdcfa560ac9423`，Actions `36363283159` 五项通过。这里是 v0.3 内部语言文本领域的增量，不改变已验证人才 2.0 的验收归属，也不是完整一期完成声明。

## 行为与读取边界

人物、作品、项目各自可以维护中文和英文内部文本；一种语言只有一份未删除文本，不按语言复制人物。四个接口为 `GET /locale-texts`、`GET /locale-texts/{id}`、`POST /locale-texts`、`PATCH /locale-texts/{id}`。请求和读取权限、回执复查、响应、审计均已登记；契约合计174条。

每次保存必须明确选择1至20份当前可读来源，同时冻结所属档案及其原始来源的版本、范围版本和保护版本。已有来源不能通过换一组新来源绕过当前限制；损坏的旧依赖同样不能由普通编辑覆盖。人物的受限交接不会自动授予语言文本读取权限，机器身份不能调用语言接口。

普通档案或来源内容变化后，原文可见但提示复核；保护状态或范围变化后，正文为空并标记受限；来源暂停、过期或失去访问范围时，详情不可读且列表不显示。归档对象只读。人工确认只表示按当前依据复核了这段文字，不把职业、资质、成年资格或其他原事实改为已核验。

页面沿用现有资料详情和专业工作台。编辑时显示所选来源，允许保存未复核草稿。保存结果未知时，文本、来源、确认选项和退出均冻结，原样重试保留请求正文和请求键。

## 数据库及维护

新增两张有类型外键的表 `localeTexts`、`localeDependencies`；同空间、唯一语言、唯一归属、依据数量、人工确认归属及已删正文为空均由数据库约束保护。提交时的延迟约束要求完整依赖图，不能单独插入无依据正文或移除必需归属。依赖不能转移到另一份文本而绕过旧图完整性检查。

第43次迁移 `202609280009_internal_locale_texts` 与第44次 `202609280010_locale_dependency_identity` 已在隔离 PostgreSQL 应用并冻结。44次迁移均未改写。43应用后的检查发现依赖改归属可能绕过旧图的延迟检查，采用追加44修复，未编辑已应用43。另在保留既有数据的42次迁移合成库上升级至44，60张原表的逐表内容摘要全部一致；没有清库或 `db push`。

来源、人物、作品、项目删除影响中逐项列出衍生文本；明确选择后冻结其文本/依赖/范围摘要。执行再次检查，业务删除、审计和条目完成同事务。清除正文及依赖，仅留下不可恢复的最小已删头；最终删除前再次确认没有遗漏依赖。删除独立依据来源不顺带删除文本所属人物。不能只换来源保留原衍生正文。

恢复检查加入语言文本计数、关系异常、原始摘要及图摘要；正文和依赖参与恢复状态摘要。真实备份中放入已人工复核文本及依赖，恢复后逐行核对，来源隔离时旧文本也不可读；不会因为恢复自动再次确认文本。
