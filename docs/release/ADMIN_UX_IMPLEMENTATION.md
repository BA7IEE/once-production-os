# 后台 UI UX 改造交付

授权：2026-10-04 用户要求“直接落地”整份后台解决方案。基线：PR #36 / `ccfe1406a77788fa01cb15290e4ccceb6b8fa382`。分支：`codex/admin-ux-solution`，叠加到 `codex/business-flow-fixes`，保持 Draft。没有合并、部署、新迁移或新增依赖；75次迁移保持原样。

## 当前实现

- 六个日常入口及收起的管理分组；工作台展示当前权限下的待办和近期档案。
- 人才库以照片结果为主，保留全部筛选维度；勾选与打开详情分开，跨页选择及返回保留上下文。
- 人才详情分为概览、基本资料、照片视频、作品与合作。姓名、个人资料、模特分类、量尺、联系方式和专业记录在对应区域维护；邀请和团队核验携带当前人才。
- 候选清单使用显式清单、范围与职业选择；整批验证后提交，重复项单独报告，不发生部分新增。新增项上限100条，选择上限200项。
- 多文件顺序上传，未知响应暂停后续文件；只读核对后明确继续，成功文件保留。媒体集合和本人作品可在当前档案选择素材及补充上传。
- 新作品命令在同一事务记录案例、具体职业署名、来源、素材顺序和封面。保留未知日期，任一项失效整批回滚，使用现有作品生命周期。
- 审核聚合本人文字/媒体提交、归属申请、来源核验和外部材料，按本人待办、本人发起和已处理组织；选择审核组会同时选择所需项目，取消时连同依赖项取消。
- 表格/CSV导入先对应字段，再服务器逐行预览、明确提交并查看真实后台结果；未知名称不猜测、不自动合并。旧JSON导入和历史修复保留在高级入口。
- 未保存内容仅在内存保护，不持久化正文。结果未知时冻结原输入，提供只读回执检查和独立的原样重试。读取和命令都绑定当前成员，身份变化清除旧显示。

使用现有React/native控件和一致的布局样式，未引入另一套组件依赖或改变业务权限。设计参考及规则见[整体方案](../design/ADMIN_UX_SOLUTION_20261004.md)。

## 验收与边界

本机 Swap 超过项目4GiB门槛，因此本地不运行构建、数据库或浏览器服务。轻量专项35/35通过，前后端类型检查通过。构建、真实PostgreSQL、真实Nest/Worker/Chromium业务链、本人端回归和本轮资源清理在新增的 `ONCE admin UX acceptance` CI 上执行。

当前证据状态：CI **NOT_RUN**；真实供应商 **PROVIDER_VERIFIED=NOT_RUN**；无提示真人可用性测试 **NOT_RUN**。设计中的耗时/通过率是待验证目标，自动化与合成数据不证明真人使用体验或真实供应商已通过。

CI证据：`artifacts/admin-ux/postgres.json`、`browser.json`与1280×800、360/390/430像素截图；原业务链及本人端回归证据分别在 `artifacts/business-flow/`、`artifacts/talent-experience-pr02b/`。资源清理以本轮 `run.json` 的 `ZERO_RESIDUE` 为准。最终提交和运行结果完成后回填。
