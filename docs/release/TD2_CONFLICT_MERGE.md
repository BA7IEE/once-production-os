## 本轮行为

- 两边均有 TalentProfile / CastingProfile 时，必须明确选择“使用主档案，保留重复档案历史”。主档案继续生效；重复记录留在原归档身份，以类型化 `supersededById` 指向主记录。UUID、原来源、字段内容、Evidence owner 不变，不拼接不同来源的字段。若要另一份作为当前资料，应交换主/重复身份再预览。
- 量尺记录仍按原 ID 迁移至主身份；历史外观档案把原当前量尺指针存入 `retiredCurrentMeasurementSetId`。现有同人物外键不被绕过。
- 重叠职业、语言、常驻地和 ACTIVE 成人资格，必须逐对选择哪边继续生效。另一边 INACTIVE，事实、来源、证据、职业依赖 ID 保留。被停用职业的关联资料不会自动换绑到另一职业，也不会继续作为可用资料。成人资格决定还需要 `sources.review`。
- 缺少、重复、非法或互相矛盾的决定均拒绝；旧预览漂移仍拒绝。业务图、决定、别名、回执、审计在同一事务，失败使用原请求键重试。
- GET `/people/{id}/merge-history` 要求 `data.merge` + `records.read`，检查当前和原人物范围、精确别名、当前来源资格及字段证据。结果始终标记不可用；无权限的行及数量不返回。读取有审计。不会返回资格密文、凭证、建议原文或证据原文。
- 人才合并页面提供逐项冲突选择、关联影响提示和“查看合并保留资料”。没有默认决定；只读历史最多显示当前可见前 100 条。这不是完整的专业工作台。

新增迁移 `202609270002_talent_merge_history`；已有迁移不改写。PrismaStore、MemoryStore 和 PostgreSQL 触发器均拒绝修改/删除已保留档案；数据库另外校验字段保真、别名链和量尺归属。当前主档案一旦承接历史，不能改变 owner 或再次成为历史记录。重复身份已有入向别名的原合并阻断继续有效。
