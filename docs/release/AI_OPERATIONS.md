# AI 后台执行与人工费用核对（2026-09-29）

本批继续 AI 业务链，补通用后台执行器、当前部署配置的批准/停用、人工费用核对和解冻页面。真实供应商适配器、密钥/定价配置加载及供应商结果查询尚未实现；普通部署不配置 AI，Worker 只隔离遗留未决请求，不会发送资料。没有生产假适配器或内存回退。

## 本批实现

- 部署配置的完整摘要、递增配置版本、恢复批次与管理员批准绑定。重新配置必须重新确认；不能用旧版本回退绕过新批准。批准人失效或失去管理员权限即停止新调用，恢复准备禁用全部旧批准。页面可以读取、批准和停用已安装的候选配置；不接受页面提交任意地址、密钥或自称验证通过。
- Worker 在短事务内重新检查原申请人、来源、许可、输入及配置，然后提交唯一发送记录；网络工作在事务外。并发 Worker 不能取得第二次发送权。任务等待过期/资格失效时关闭未发任务并释放预留；存储/审计暂时失败不伪装为业务取消。
- 有界请求支持停止信号和绝对截止时间。遗留 MAY_HAVE_EXECUTED 超过 130 秒转 UNKNOWN，继续保留费用，永不自动接管重发。正式后台已接入此隔离周期；发送执行器需要安装身份匹配的真实适配器后才能启用，当前为空。
- 管理员按原供应商身份、请求编号与已核验的当前可见来源登记费用核对。人工确认已执行或者未执行均关闭旧任务，不生成建议，不自动重发；已确认未执行必须零费用。账本、不可改的核对证据关联、操作者、审计和回执同事务；不复制证据正文到普通日志或审计。
- 超额冻结后，先核清全部未决请求，再根据当前批准的每日限额人工解冻。保留超额金额和独立不可改的解冻记录；数据库拒绝没有匹配记录的解冻。核对和解冻的丢响应重试复用原请求键。
- 管理页仅展示配置/金额/请求编号，不把管理权限变成业务正文权限。证据读取仍受来源范围和 sensitive.read 控制。来源后续清理遵守原规则，核对只保留最小关联与金额，不保留正文副本。
