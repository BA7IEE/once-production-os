# 上线前运行故障修复

审查基线：406827d；本批只修复两项已复现故障，不扩展业务功能，不修改54次冻结迁移。

## 实现

- 安全日志使用 fs-ext 2.1.1 的非阻塞 flock，锁文件保持同一 inode；进程关闭或 SIGKILL 后由内核释放，不能通过等待超时抢占活进程。首次创建日志同样持锁，防止读取尚未写完的头。异常退出不会抹除既有日志，也不会自动截断残缺记录。
- ready 检查验证安全日志完整性、锁获取和可写打开/fsync；持锁超时、日志损坏、权限或I/O失败返回503。短时正常锁竞争最多等待2秒，存活检查不受影响。
- 媒体维护每轮最多处理4条清理，单条失败保留未确认状态并延后60秒再试；其他清理和新上传继续，不虚报物理删除完成。重启后重新核对当前资格和对象状态。

## 运行约束

API、Worker及恢复命令必须使用同一主机的本地文件系统／同一共享本地卷及相同锁文件；不支持NFS/SMB。不删除或替换运行中的.lock文件。停止全部旧版本进程后再升级，不能混跑目录锁旧版本与文件锁新版本；旧开发目录若残留.lock目录，需要确认全部旧进程已停止，再人工核对空目录后处理。系统不会自动删除未知目录。

新增原生依赖仅用于内核锁；Docker构建阶段安装Python/make/g++，运行阶段不增加编译工具。Linux和macOS是本批验证目标，Windows未验。

## 实测与边界

本机类型检查通过；37项受影响回归通过，包含真实子进程SIGKILL、存活进程互斥、异常释放、日志残缺拒绝、清理失败继续及延后重试。原有恢复差额、安全意图及COS合同测试一起通过。
