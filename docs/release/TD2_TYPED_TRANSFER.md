## 已实现的完整子集

新格式 `once-export-v2-talent` 包含 `once-talent-transfer-v1` 专业清单。八个显式白名单分组：

| 分组 | 导出内容 |
|---|---|
| talentProfiles | 当前主档案内部简介、状态 |
| personRoles | 职业代码、有效期、状态 |
| personLanguages | 语言、四项熟练度、有效期、核验时间、状态 |
| talentLocations | 常驻/服务地点、有效期、核验时间、状态 |
| measurementSets | 原量尺值与尺码体系、日期精度、前序记录、状态 |
| castingProfiles | 发色/瞳色、观察日期、当前量尺关联 |
| translatorLanguagePairs | 翻译方向、对应职业、状态 |
| translatorServiceModes | 翻译服务方式、对应职业、状态 |

每条记录保留 UUID、personId、自己的 sourceId、版本及原创建/更新时间。没有从数据库行直接整对象输出；新增模型字段不会自动进入白名单。所选分组导出其全部当前可读记录（含停用状态），最多 500 条；无法读取任一所选行/字段会拒绝，不静默过滤。依赖必须显式一起选择，例如翻译方向需职业，当前量尺需完整量尺链，选角资料需专业主档案与适用职业。不能混入旧扁平专业字段。

这个格式是受控业务迁移，不是完整档案备份。人物基本字段、完整来源字段仍要分别明确选择；重建要求至少有姓名、人物状态以及所有引用来源的完整八项来源字段。纯字段导出可以少选，缺必需字段的文件不能用于重建。

## 双层许可和失效

- 保留既有 PERSON 精确许可：每个所选人物的基本字段和专业分组必须得到批准。
- 每一实际事实来源另需 SOURCE 许可，明确包含该来源输出的专业分组。源许可不是选人许可；没有 PERSON 许可不能导出该人物。已有 sourceId/personId 复合外键不放宽，不把第二来源伪装为人物主来源。
- 许可创建要求 sources.review，来源当前有效、INTERNAL_USE、许可期限不超过来源期限；资料范围继续在服务端复查。
- 申请/worker/下载都检查当前身份、来源、范围和许可。专业行内容、关联或版本变化使冻结文件失效；专业来源版本变化、许可撤销、账号停用也阻断。旧 v1 的普通内容编辑快照规则保留。
- 同一事实含其他来源的字段 Evidence 时返回 `TD2_EXPORT_EVIDENCE_UNSUPPORTED`；尚未具备逐字段来源迁移格式，不能丢掉它再声称完整重建。
- 业务清单、依赖、审计与回执沿用原同事务流程；download 审计仍在响应数据之前完成。

## 重建

沿用受限 `pnpm rebuild:json`：只接受明确 loopback `once_rebuild_*` 目标；唯一已激活管理员、bootstrap 范围、空业务库。默认预检；写入要 `ALLOW_REBUILD=yes --apply --expected-sha256 <原导出摘要>`。不改库、不清库、不覆盖、不自动安装 migration。

v1 继续兼容，v2 内外版本必须一致。解析拒绝未知字段；预检检查 UUID 唯一、对象/来源/职业/量尺依赖、翻译职业和方向、字典、有效期重叠、量尺日期/尺码体系/历史循环/当前确认状态。业务记录和 `rebuild.apply` 审计同事务。审计失败全部回滚；重试后原 ID、来源、字段与关联保持。已写入目标不能再次应用。

不生成过去的 Evidence、Machine secret、Proposal 或旧审计。原记录的已导出状态/核验时间属于输入快照，不虚构核验人；重建操作记录自己的审计。来源沿用原重建器的 BASELINE 规则，目标范围/维护人为本地管理员。
