## 实现范围

新增第十一个显式专业分组 `person.td2.representations`：代表关系、职业关联、代表机构或个人、服务地区、有效期与启停状态，连同原 UUID、人物、来源、版本和创建/更新时间迁移。机构与个人必须且只能选择一个，个人不能代表自己；不自动合并或替换关系，不重新启用停用关系。

机构只导出实际引用项，与外部标识共用同一机构时按 ID 去重。机构来源许可必须覆盖本次使用它的每个专业分组；仅批准外部标识不能顺带导出代表关系。机构范围/来源当前不可读，整份导出拒绝。

个人代表必须在所选人物中，并取得该人物的独立 PERSON 许可及所需来源许可。不会把关联联系人自动加入导出。所选人物若还有被选择分组中的关联，也必须完整选择并批准，缺依赖明确拒绝。职业关联保持原人物/原职业编号，不得改绑到另一个人的职业。

生成、worker、下载继续检查当前身份、范围、来源、许可与清单摘要。代表人许可撤销、范围丢失或关系事实变化会让排队任务与旧下载失效。保留原代表人身份，联系方式不属于本格式。

选代表关系时使用内层 `once-talent-transfer-v4`，外层仍为 `once-export-v2-talent`。原 v1/v2/v3 分支严格保持原结构与摘要，不附加空代表关系表。只选代表关系、不选能力或外部标识也能独立输出实际所用机构。

## 重建和迁移

沿用唯一管理员、隔离空目标、先预检后应用和原摘要校验。先重建所选人物/机构，再写代表关系，全部业务与审计同事务。失败后人物、字典、机构均无残留。所有关联 UUID、原来源、有效期及停用状态保持；目标范围按既有 bootstrap 契约映射，不复制原权限。拒绝缺代表人、双主体、无主体、自我代表、缺职业/机构和非法有效期。
