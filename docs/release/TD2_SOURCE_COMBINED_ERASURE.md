# 专业资料与原件联合清理

同一来源同时拥有专业事实与原件时，现在共用一张冻结关系图。每项专业资料仍须明确选择删除，或以已经登记的完整独立字段依据保留；原件引用、资格失效、集合重排和专业事实处置在同一事务执行。不会先执行一组，再因它改变了另一组的摘要而卡住。

保留集合可移出本次删除的原件、保留其他来源的图片和剩余顺序；集合自身的标题、类别、职业、状态和原始来源不改。整组摘要仍绑定完整行和版本，单项完成验证绑定业务内容，允许本次已评估的集合版本变化。完整 SHA-256 摘要使用 base64url 编码放入有限长度的记录字段，不截断摘要、不修改历史数据库约束。

保留资料不能继续指向待删除证明原件。其他来源的证明资格会按既有规则失效，核验历史保留。集合和原件共同删除时，重复引用只处理一次。整组审计写入失败，事实、候选职业上下文、引用、资格和建议全部回滚；重试成功后才逐项登记回执，再由物理清理器销毁文件。

最终完成前再次检查保留事实及父级、人物、来源、媒体、机构等的当前范围与独立字段依据。范围失去时保持 CLEANING 和来源阻断，恢复范围后可继续；不会仅凭此前成功的回执宣告完成。

页面连续决定时发现摘要和列表分别刷新造成旧版本提交。现共用一批读取结果，在新摘要和列表均返回前禁用下一项决定、冻结和清理动作。浏览器用暂停申请读取响应的方式验证按钮确实锁住，然后释放响应继续；不加等待时间、不刷新页面、不取消版本检查。

验证记录：核心回归432/432 CORE_MEMORY_TESTED；联合处置/审计回滚/重试/实际文件销毁及最终范围变化已在真实 PostgreSQL 测试；完整数据库链 DB_TESTED。类型、契约、静态检查及完整构建 PASS。真实 Chromium 联合保留/删除、两份原件实际消失及延迟刷新期间按钮锁定 BROWSER_TESTED。

测试期间记录两项真实问题：第一次 PostgreSQL 创建申请因单项双摘要超出既有120字符约束被拒绝，改用整组完整冻结摘要和单项业务内容摘要后通过；第一次连续页面决定因旧版本收到409，修正刷新衔接后重新验收。延迟响应的测试首次在解除拦截前未等待请求继续完成，触发 Route is already handled；已等待请求完成后再解除该拦截。首次合成集合请求使用错误路由也已纠正，未改变接口。
