# 人才 2.0 旧查询兼容与专业写入保护

旧 `/people` 列表和详情原来直接使用 Person 的历史职业、语言、城市和身高。新工作台修改关系表后，旧列表会漏掉新职业，也可能继续显示已停用的旧职业；旧编辑器还可以改写旧字段，产生两套相互矛盾的数据。

本批让已经进入 2.0 的人物使用同一份当前可见专业事实生成旧版响应和筛选条件。职业、语言、能力、当前 BASE 地点以及当前已确认量尺都经过原有来源、范围、状态和有效期检查。没有有效事实时返回空或未知，不回退读取历史列。原身高尚未人工复核时仍为未知。

新增响应标记 `professionalManaged`，不新增操作或扩大权限。旧编辑页对这些人物只提交基本身份字段，提示职业、语言、所在地和量尺到专业工作台维护。服务器同时拒绝旧专业字段写入（`TD2_TYPED_WRITE_REQUIRED`）和对旧专业字段的核验（`TD2_TYPED_EVIDENCE_REQUIRED`），仅隐藏表单不能代替这个保护。

## 权限与历史边界

- Person 原编号和历史列不改写；没有数据库迁移，42 次冻结迁移原样保留。
- 已升级档案和无职业普通联系人都不能退回旧专业写入口。仍未升级的旧版档案暂时保持原契约，继续通过显式升级进入新关系。
- 旧列表仍采用原基本档案的访问规则；本批没有用兼容查询扩大原来源或交接权限。专业检索继续支持独立来源事实的专门访问语义。
- 交接仅授予基本档案；如果接收人没有专业资料的当前范围，即使是 ADMIN，旧列表和详情也不会绕过范围显示专业事实。接收人仍能按已有交接权限编辑基本简介。
- 旧专业字段核验证据仍在数据库保留，但不再作为当前专业事实的核验状态显示；新专业事实使用各自的类型化证据。

## 验证

`tests/support/talent-legacy-projection.ts` 由核心测试和真实 PostgreSQL 领域套件共同调用：先建立旧档案并显式升级，新增职业/语言、停用原职业，对照新旧查询；阻断五类旧字段写入和旧字段核验，确认拒绝后版本不变；独立来源暂停后即刻遮蔽语言；最后全部职业停用不回退显示历史职业。另一用例通过正式创建/接受交接，验证受限专业资料不泄露且基本编辑仍可用。

浏览器扩展在真实专业工作台建立模特兼翻译并确认量尺后，返回旧详情，检查当前双职业；进入旧编辑页，确认不显示专业编辑控件，实际保存基本别名，并检查请求没有五类旧字段、数据库旧职业数组仍为空而新职业关系完整。

本批最终核心回归 460/460 CORE_MEMORY_TESTED，专项 2/2；类型、请求契约、静态检查、生产构建和 transport 类型 PASS。真实 PostgreSQL 的领域及兼容套件 19/19 DB_TESTED，带旧数据升级通过；完整 PostgreSQL 链 DB_TESTED（含原合同 67/67、旧基线升级、全部既有重建/恢复及回滚/重试）。完整真实 Chromium 浏览器 BROWSER_TESTED，包括旧编辑请求与数据库关系断言。前批 `9e00b53` 对应 Actions36359307865 已确认五条成功；本批新 head 需独立验证。证据：`artifacts/td2-legacy-projection-20260928/`。未合并、未部署。

## 尚不等于整个 Phase C 完成

旧结构化检索 `/talent-search` 的兼容接线、仅鞋码量尺误关闭旧身高复核问题继续修复。旧建档和有限导入入口仍保留旧版契约，既有旧档案仍须显式升级和人工迁移复核；本批没有把这些入口无提示改成另一套业务。完整迁移一致性清零前不能删除历史列，不能用本次兼容修复宣称 Phase D 已满足条件。
