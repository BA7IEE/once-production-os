## 1. 实际改动

### 1.1 失败导入的显式继续

新增 `POST /api/v1/jobs/{id}/resume`，请求体 `{"expectedRevision":3}`，必须携带当前登录会话、CSRF 和 `Idempotency-Key`。首次成功返回 `202` 和 `ACCEPTED`，仍是排队回执，不是完成结果。

仅允许本人发起、`FAILED` 且错误为 `STORE_BUSY` / `STORE_UNAVAILABLE` 的任务；全部领取次数上限为 3，显式继续不清零计数。继续前复查当前身份、角色、资料来源、范围、来源版本、预览有效期和已入库检查点。不得给旧批次换来源版本、改选中行集合、清除已入库行或重新创建整个任务。

原命令重放依旧只返回原回执，不会暗中重新排队。命令回执、排队状态变更和审计在同一事务中。随后每行执行继续沿用既有资格与租约检查。

任务 DTO 新增 `importedCount`、`selectedCount`、`canResume`、`resumeBlockedReason`；前端提供“继续处理未完成行”、部分完成提示和未知响应的原样请求入口。最终态以任务查询为准。

### 1.2 预览查询去放大

人才可见性改为在同一个短事务内批量读取来源／范围／范围成员，按原有可见性口径过滤。导入预览仅构造一次可见姓名集合和一次有效字典集合，每一输入行不再调用完整人才列表。

100 人 × 100 行的合成测试中，读取调用数为 **12**，原反例为 30,207。这里计量 Store `get/find` 次数，不是数据库耗时、吞吐或压力测试。

**仍保留的约束**：当前适配器仍使用全局事务锁，查询仍存在工作空间全量读取和应用层分页。本补丁消除 N×M 查询放大，但不宣称完整 SQL 授权分页或规模性能验收；不能为了提速直接删锁。

### 1.3 来源版本及独立决定

新增 `sourceHistory`：在同一事务中追加来源快照、来源版本号、操作人、动作、独立暂停原因和当时范围。创建、编辑、核验、暂停、范围变化全部留记录。暂停不再覆盖 `sources.basisDescription`。

这是一张来源域的版本／决定记录表，不是通用事件平台。稳定 `SourceRecord` 仍表示当前状态；旧状态与决定理由在追加历史中独立保存。历史写入失败时整个业务命令回滚。适配器禁止修改／删除历史；SQL 另有不可改触发器和复合外键。

新增 `GET /api/v1/sources/{id}/history?page=1&pageSize=20`。它是**明确的受限证据复核入口**，要求 `sources.read` + `sources.review` + `sensitive.read`，并取当前来源范围与每条历史范围的交集。历史原文读取记审计；普通来源／人才读取在暂停或过期后仍阻断。管理员没有默认绕过。审计只记录元数据，不复制原文或原因。

历史入口允许具备以上权限的复核者查看已暂停来源的证据；这不等于恢复资料使用资格。前端按权限显示独立历史按钮，并明确提示用途。

### 1.4 既有数据升级与真实性

新增迁移 `prisma/migrations/202609230001_source_history/migration.sql`。初始迁移完全不改。

迁移为每条现存来源建立 `BASELINE` 记录，保留迁移时实际可见状态，`actorId=null`、`baselineOnly=true`。不伪造创建者、核验者或之前的版本。

旧代码已暂停的来源可能把暂停原因放在依据字段。对此设置 `basisAmbiguous=true`；前端明确提示不能当作原使用依据。后续范围／编辑变化继续携带这个不确定性，只有明确的新核验才对新版本清除标记，旧历史保持原样。已丢失文本不能由本补丁恢复。

历史断档时，新的来源变更返回 `HISTORY_BASELINE_MISSING`，不自动编造缺失版本。迁移及新代码启用期间必须停止旧 API/Worker，避免旧进程继续进行不带历史的写入。

### 1.5 数据库测试补强

真实 PostgreSQL 测试改为通过领域命令，在历史、人才、审计、回执插入**之后**分别注入错误，验证来源／历史／人才／审计／回执全部回滚，并保留同键成功重试和重放对照。

同时增加历史唯一约束／跨空间外键／不可改触发器、部分导入续跑、100／1,000 人配合 100 行预览的实际查询计数测试。专用数据库必须是新的、空的 `once_test_*`；测试不清空、不删除旧库。

## 3. 在本地验证

1. 停止 API/Worker，保留 `.env`、`.secrets`、旧数据卷和旧测试库。不要再次运行初始化脚本，也不要清库。
2. 在隔离分支应用补丁并执行 `pnpm install --frozen-lockfile`。本补丁未改 `package.json`、依赖版本或锁文件。
3. 执行 `pnpm exec prisma validate`、`pnpm db:generate`、`pnpm contract:check`、`pnpm typecheck`、`pnpm typecheck:transport`、`pnpm test:core`、`pnpm build`。
4. 对既有**合成开发库**完成备份后，启动其原数据库容器，确认 `DATABASE_URL` 指向开发库，再 `pnpm db:deploy`。检查旧记录仍存在、每条旧来源有 BASELINE；暂停行保留不确定标记。
5. 另建新 `once_test_*` 专用空库。明确设置 `DATABASE_URL_TEST`，用它应用全部迁移，再运行 `ALLOW_DB_TESTS=yes pnpm verify:postgres`。不要重用已留合成记录的旧测试库。
6. 浏览器验证来源历史按钮的权限、暂停／复核后历史变化、部分完成任务恢复、网络未知时原样核对、来源／范围失效后的拒绝。不得在正式库人为注入错误；故障注入工具只在 tests 中。
7. 重跑并记录本地新结果后再提交。保留旧报告为历史，追加当前报告，不把本补丁的未执行项写成 PASS。
