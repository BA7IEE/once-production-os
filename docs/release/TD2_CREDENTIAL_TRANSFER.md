## 当前可用范围

新增 `person.td2.personCredentials` 和独立的 `person.td2.credentialIdentifiers` 许可，以及内层 `once-talent-transfer-v6`。无证明附件的 UNVERIFIED/REVOKED 资质可按原ID、职业、来源、颁发机构/名称、起止日期和原状态迁移，不重新激活撤销或过期资质。颁发机构仅迁移所用记录，并单独检查其来源对资质组的许可。可与上一批字段证据迁移组合，保留来源与原核验归属。

编号默认不导出。资质含编号时，缺少独立编号许可即整条阻断，不静默丢弃编号；人物与实际资质来源都要批准该字段组，操作者当前须有 sensitive.read。JSON 只携带原 AES-GCM 密文、遮罩和原工作空间绑定，不解密成明文，不携带密钥。证据字段禁止引用编号密文/遮罩，不额外导出其摘要。

后台和下载复查资格、范围与用途许可；编号、资质、颁发机构或所选证据变化使旧快照失效。持有旧文件不代表有新的读取许可。旧 v1-v5 保持结构与摘要规则；无编号资质不要求敏感编号许可或密钥文件。

## 隔离重建及密钥

已有 `rebuild:json` CLI 仍只接受隔离空库及原导出摘要。若文件含加密编号，CHECK 和 APPLY 都必须提供：

- `REBUILD_SOURCE_CONTACT_KEY_FILE`：原环境实际使用的编号/联系资料密钥文件。
- `CONTACT_KEY_FILE`：目标环境实际配置使用的密钥文件，必须与随后运行的目标服务一致。

均为64位十六进制密钥文本，常规文件、权限0600或0400，不接受符号链接或组/其他用户可读文件。文件在数据库事务前读取，不把路径、内容或解密明文写入普通错误输出。旧格式和无编号文件不读取这些配置。

CLI 在写入前用“原工作空间 + 资质ID”校验解密和遮罩；成功后用“目标工作空间 + 原资质ID”和目标密钥重新加密。目标当前管理员须有 sensitive.write；事务中复查当前管理员身份与敏感写权限，不依赖事务前捕获的权限。缺密钥、错误密钥、篡改绑定/密文/遮罩一律拒绝。业务、字段证据和审计同事务，审计故障整批回滚，正确重试后才能完成。

CHECK 不写入数据；APPLY 沿用 `ALLOW_REBUILD=yes` 与 `--expected-sha256`，没有放宽目标空库或摘要校验。CLI 输出计数与摘要，不输出编号、密文或密钥。
