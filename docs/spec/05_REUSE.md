## 1. 证据与本轮边界

沿用前轮只读审查的固定提交 `fc7471efadaf22834d5effb0b92a9fdd034bea2b`。package.json中的0.72.0、AI目录声明、鉴权耦合、存储/幂等/Worker实现均是历史定向源码证据，不是本轮重新抓取的仓库最新状态。来源路径与原审查证据见13。

本轮修改复用方案的**范围与验证对象**，没有下载新提交、抽取代码、运行编译/测试或创建PR。当前不能报确定复用比例或节省天数。

## 2. 推荐方法不变，消费者改变

独立ONCE仓库、数据库、secret和测试资料；不把SRVF整仓改名，不复制救援业务数据/品牌/历史迁移。先抽小机制及相应测试，独立运行后再决定多搬多少。

原来X3围绕发布模拟，现在改为内部批次/导出/媒体任务；官网适配、公开投影、客户分享都不参与当前代码提取。未来是否公共化不影响今天已有通用机制的复用。

## 4. 不带入的内容

队员、招新、实名、考勤、报名、贡献、救援组织树、保险和旧迁移；当前不需要的机器OAuth/委托；整套通知中心；所有网站/客户侧发布业务。前端仍需独立开发，本次证据不能证明SRVF已有可直接搬用的ONCE管理台。

若抽取一个机制牵入大量无关模块，改用更窄的策略/测试经验，独立实现。避免为“减少写代码”而增加运行复杂度。内部字段/关系按新PRD建立，不用Member换名变Talent或Activity换名变Project。

没有官网供应商验证任务，没有预建CMS适配器，也没有以发布模拟通过作为OS骨架完成条件。
